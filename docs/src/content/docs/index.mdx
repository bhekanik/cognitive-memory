<section>
<span class="section-marker">§ The opening</span>

A user asks an assistant: *which day was the beach plan?* The system has the trip. It has Tampa. It has Sarah. It has Thursday. None of it surfaces. The data is present; the right fact lost the retrieval competition.

This started in a real product (a chat app I built) and turned into the unsettling realisation that retrieval is not memory. Context windows are not memory either. What's missing is the middle.

</section>

<section>
<span class="section-marker">§ Three ideas</span>

### 01. Memory is a lifecycle.

Memories are written, maintained, retrieved, used, revised, and sometimes deliberately made harder to access. The lifecycle has design surface — and most of it is open.

<Figure number="1" caption="Six stages: extraction, embedding, storage, decay, retrieval, consolidation. Each stage has knobs.">
  <MemoryLifecycle />
</Figure>

### 02. Availability is not the same as accessibility.

Tulving's distinction from cognitive science. A memory can exist in storage and still be practically forgotten because ranking never surfaces it. We keep them separate: every memory has a retention score; ranking blends similarity with retention rather than collapsing them.

<PullQuote cite="Tulving & Pearlstone, 1966">
A memory can be unavailable for retrieval without being erased.
</PullQuote>

### 03. Forgetting is control, not data loss.

Nothing gets deleted. Memories fade — but never to zero. The 0.02 floor keeps a six-month-old fact recoverable when the right cue arrives. Core memories floor at 0.60 and stay strongly available across months of disuse.

<Figure number="2" caption="Retention over 180 days. Both floors are explicit — regular memories never reach zero, core memories stay above 0.60.">
  <DecayCurve />
</Figure>

<section>
<span class="section-marker">§ Retrieval</span>

## Similarity meets retention.

<Figure number="3" caption="Vector recall, retention-weighted scoring, optional LLM rerank. score = sim · R^0.3.">
  <PipelineDiagram />
</Figure>

The exponent softens the decay penalty: a memory at 20% retention keeps 62% of its similarity score. Old-but-relevant beats recent-but-marginal. Tune the exponent through `retrieval_score_exponent` if your domain wants more or less of the past.

<span class="section-marker">§ Code</span>

## Two voices, one shape.

<Tabs syncKey="lang">
  <TabItem label="Python">
    ```python
    from cognitive_memory import CognitiveMemory, MemoryCategory

    mem = CognitiveMemory(user_id="alice")              # user_id is per-instance (v0.4.0)

    await mem.add(
        "Alex is allergic to peanuts",
        category=MemoryCategory.CORE,
        importance=0.95,                                # core memories floor at 0.60
    )

    response = await mem.search("food allergies?")
    for r in response.results:
        print(r.memory.content, r.combined_score)      # combined = sim · R^0.3
    ```
  </TabItem>
  <TabItem label="TypeScript">
    ```typescript
    import {
      CognitiveMemory,
      InMemoryAdapter,
      HashEmbeddingProvider,
    } from "cognitive-memory";

    const mem = new CognitiveMemory({
      adapter: new InMemoryAdapter(),
      embeddingProvider: new HashEmbeddingProvider(),
      userId: "alice",                                  // userId is required (v0.4.0)
    });

    await mem.store({
      content: "Alex is allergic to peanuts",
      category: "core",
      importance: 0.95,                                 // core memories floor at 0.60
    });

    const { results } = await mem.search({ query: "food allergies?" });
    for (const r of results) {
      console.log(r.memory.content, r.combinedScore);  // combined = sim · R^0.3
    }
    ```
  </TabItem>
