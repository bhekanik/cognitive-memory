## Overview

The Postgres adapter is the recommended TypeScript choice for production deployments. It uses pgvector for vector similarity search, supports concurrent access, and scales beyond the brute-force local adapters.

## Installation

```bash
npm install cognitive-memory pg
```

The `pg` package is a peer dependency — install it alongside the TypeScript SDK.

## Setup

### Prerequisites

1. PostgreSQL 14+ with the pgvector extension:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

2. A connection string:

```
postgresql://user:password@localhost:5432/memories
```

```typescript
import { CognitiveMemory } from "cognitive-memory";
import { PostgresAdapter } from "cognitive-memory/adapters/postgres";
import { Pool } from "pg";

const pool = new Pool({
    connectionString: process.env.DATABASE_URL!,
});
const adapter = new PostgresAdapter({ pool });

const mem = new CognitiveMemory({
    adapter,
    embeddingProvider: myEmbedder,
    userId: "user-123",
});
```

## Schema

The adapter auto-creates tables on first use:

```sql
CREATE TABLE memories (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id TEXT NOT NULL,
    content TEXT NOT NULL,
    embedding vector(1536),
    category TEXT NOT NULL DEFAULT 'semantic',
    importance REAL NOT NULL DEFAULT 0.5,
    stability REAL NOT NULL DEFAULT 0.3,
    access_count INTEGER DEFAULT 0,
    last_accessed BIGINT,
    retention REAL DEFAULT 1.0,
    metadata JSONB,
    is_cold BOOLEAN DEFAULT false,
    cold_since BIGINT,
    days_at_floor INTEGER DEFAULT 0,
    is_superseded BOOLEAN DEFAULT false,
    superseded_by TEXT,
    is_stub BOOLEAN DEFAULT false,
    contradicted_by TEXT,
    semantic_type TEXT DEFAULT 'other',
    valid_from BIGINT,
    valid_until BIGINT,
    ttl_seconds INTEGER,
    source_turn_ids TEXT[] DEFAULT '{}',
    created_at BIGINT NOT NULL,
    updated_at BIGINT NOT NULL
);

CREATE TABLE memory_links (
    source_id UUID REFERENCES memories(id),
    target_id UUID REFERENCES memories(id),
    strength REAL NOT NULL DEFAULT 0.5,
    created_at BIGINT NOT NULL,
    updated_at BIGINT NOT NULL,
    PRIMARY KEY (source_id, target_id)
);

-- HNSW index for fast vector search
CREATE INDEX ON memories USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 64);

-- Query optimization indexes
CREATE INDEX ON memories (user_id, is_cold, is_stub);
CREATE INDEX ON memories (user_id, retention);
```

## Vector search performance

pgvector with HNSW indexing provides approximate nearest neighbor search in sub-100ms, even at millions of rows.

| Memory count | Brute-force (InMemory) | pgvector HNSW |
|-------------|----------------------|---------------|
| 1,000 | 2ms | 1ms |
| 10,000 | 15ms | 2ms |
| 100,000 | 150ms | 5ms |
| 1,000,000 | 1,500ms | 10ms |

### Tuning HNSW parameters

```sql
-- Higher ef_search = more accurate but slower
SET hnsw.ef_search = 100;  -- default: 40

-- Higher m = more connections per node, better recall
-- Set at index creation time
CREATE INDEX ON memories USING hnsw (embedding vector_cosine_ops)
    WITH (m = 32, ef_construction = 128);
```

## Lexical search

The Postgres adapter supports `search_lexical` / `searchLexical` using PostgreSQL's built-in full-text search (`ts_vector` / `to_tsquery`). When hybrid search is enabled, the adapter combines pgvector similarity results with lexical matches for improved retrieval accuracy. The required `tsvector` column and GIN index are auto-created alongside the schema.

## Multi-tenant usage

The Postgres adapter naturally supports multi-tenancy through the `user_id` column. All queries are scoped to the current user:

```typescript
const memAlice = new CognitiveMemory({ adapter, embeddingProvider, userId: "alice" });
const memBob = new CognitiveMemory({ adapter, embeddingProvider, userId: "bob" });
```

## Transactions

The Postgres adapter supports real transactions:

```python
await adapter.transaction(async (txn) => {
    const id1 = await txn.createMemory(memory1);
    const id2 = await txn.createMemory(memory2);
    return [id1, id2];
});
```

## Connection pooling

For production, use connection pooling:

```python
const pool = new Pool({
    connectionString: process.env.DATABASE_URL!,
    max: 20,
});
const adapter = new PostgresAdapter({ pool });
```

## When to use

- Production web applications
- Multi-user systems
- Large memory collections (10,000+ memories)
- Any scenario requiring concurrent access
- When you need reliable, battle-tested infrastructure

## When NOT to use

- Quick prototyping (use InMemory)
- Serverless functions with cold starts (use Convex)
- Scenarios where you can't run Postgres
- Python projects using only the current Python SDK adapters
