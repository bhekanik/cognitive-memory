## What are multi-hop questions?

Multi-hop questions require combining information from two or more stored memories.

**Single-hop example:** "What is Alex's job?" only needs "Alex is a software engineer."

**Multi-hop example:** "What does Sarah's brother do for a living?" needs "Sarah has a brother named Tom" and "Tom works as a dentist."

This matters because vector search retrieves each memory independently. A memory can be necessary for the answer even if it is not very similar to the query.

## Why associations help

When related memories are encoded or retrieved together, Cognitive Memory stores an association between them. Later, retrieving one memory can activate linked memories even if those linked memories would not rank highly by query similarity alone.

That is the intended role of the association graph: bridge facts that belong together but do not all look like the user's exact question.

## Why deep recall helps

Consolidation can move originals out of the normal search path. Deep recall brings cold and superseded records back into the candidate set, while still excluding stubs. That gives the system a way to recover exact names, dates, and details when summaries are not enough.

## Takeaway

Multi-hop is not "the" memory benchmark. It is a useful lens for one part of memory: whether a system can connect facts across time and context. If your application mostly needs isolated factual lookup, multi-hop matters less. If it needs personal-assistant-style reasoning over weeks or months, it matters a lot.
