## Retrieval semantics

All current SDK benchmark runs use the v6-style search pipeline:

<Tabs syncKey="lang">
  <TabItem label="Python">
    ```python
    response = await mem.search(
        question,
        top_k=20,
        deep_recall=True,
        trace=True,
    )
    results = response.results
    ```
  </TabItem>
  <TabItem label="TypeScript">
    ```typescript
    const response = await mem.search({
      query: question,
      limit: 20,
      deepRecall: true,
      trace: true,
    });
    const { results } = response;
    ```
  </TabItem>
</Tabs>

The canonical score is:

```text
score(m, q) = sim(m, q) * R(m)^alpha
```

Default `alpha` is `0.3`. Normal search excludes cold, superseded, and stub records. Deep recall includes cold and superseded records while still excluding stubs.

When reranking is enabled, the engine retrieves `top_k * rerank_factor` candidates, reranks that expanded pool, then returns `top_k`.

## LoCoMo

LoCoMo uses 10 conversations and 1,540 category 1-4 QA items for the standard result. The active current-refresh artifact reports:

| Metric | Result |
|--------|:------:|
| Overall token F1 | 44.8% |
| Multi-hop token F1 | 48.5% |
| Judge accuracy | 58.4% |

Oracle-evidence analysis reports 63.9% LoCoMo-scoring F1 and 61.1% Mem0-scoring F1.

## LongMemEval-S

## LTI-Bench v2

LTI-Bench is a controlled 42-probe harness for lifecycle behavior. It is not a broad generalization benchmark.

## Historical runs

Older labels such as Run A, Run B, Run F, Run H, Run L, and Run M remain useful in experiment logs and paper-adjacent notes, but public docs should not present them as the active benchmark taxonomy unless the page clearly marks them as historical, pilot, or ablation results.
